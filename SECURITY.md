# Security policy

This experimental prototype has no production support or guaranteed response SLA. Only the current source tree is maintained; no stable supported release series is declared.

Do not use GlassWrite for secrets or regulated/confidential material. Accessibility access is broad, detection depends on host-app metadata, and the final write cannot be atomic. See README for the privacy boundaries and residual risks.

Report security problems privately using GitHub's **Report a vulnerability** if private vulnerability reporting is enabled on the published repository. If it is not enabled, contact the repository owner through a private channel before disclosing details; maintainers should enable it before publication. No dedicated security email is advertised here. Do not place exploit credentials, captured user text, personal records, private endpoints or unredacted logs in public issues. Supply a minimal synthetic reproduction, affected symbols, expected behavior and environment/version metadata.
